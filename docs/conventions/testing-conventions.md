# Testing Conventions

## 1. Naming

| Type | Pattern | Example |
|------|---------|---------|
| Test file | `test_<module>.py` | `test_items.py` |
| Test function | `test_<scenario>` | `test_send_text_success` |
| Test class | `Test<Component>` | `TestSendEndpoint` |

## 2. Test Structure

Tests are async by default (`asyncio_mode = auto` in `backend/pytest.ini`), so no
`@pytest.mark.asyncio` decorator is required.

```python
class TestSendEndpoint:
    async def test_send_text_success(self, client):
        resp = await client.post(
            "/api/send",
            data={"kind": "text", "text": "hello world", "ttl": "300"},
        )
        assert resp.status_code == 200
        assert len(resp.json()["code"]) == 12
```

The `client` fixture in `tests/conftest.py` enters the FastAPI lifespan explicitly
(httpx's `ASGITransport` does not run startup/shutdown), so the database, storage,
cache, and purge worker are initialised for every test.

## 3. Test Data Conventions

- Use non-sensitive placeholder data
- Codes are generated by the app — never hardcode a real one
- Use a temporary `CLIP_DATA_DIR` (handled by `conftest.py`)
- Prefer forcing expiry via `deps.db.execute(...)` over `time.sleep()`

## 4. Security Test Conventions

Every security fix must have a corresponding test:

| Fix | Test |
|-----|------|
| SQL injection | Malicious code returns 400 |
| Executable rejection | ELF binary returns 422 |
| XSS escaping | `<script>` stored literally |
| Rate limiting | 429 past the configured limit |
| Path traversal | Filename reduced to basename |
| Brute-force lockout | 423 after `CLIP_MAX_FAILED_ATTEMPTS` |
| Admin auth | 401 without a valid bearer token |

## 5. Where to Place Tests

```
backend/
  tests/
    __init__.py
    conftest.py        # env isolation + client fixture
    test_api.py        # API endpoints
    test_security.py   # security controls
    test_storage.py    # storage backends
    test_rate_limit.py # slowapi behaviour
    test_filetype.py   # MIME detection
    test_admin.py      # admin API
```

## 6. Running Tests

```bash
cd backend
pip install -r requirements-dev.txt
pytest tests/ -v
```

Useful invocations:

```bash
pytest tests/test_api.py -v              # one file
pytest tests/ -k security -v             # by keyword
pytest tests/ --maxfail=1                # stop on first failure
```

## 7. Coverage Target

- Lines: 80%
- Branches: 70%
- Security-critical paths: 100%
